# TrustVault threat model

**Review basis:** source migrations, Edge Functions, frontend, and test definitions were inspected on 2026-10-20. A focused review found and fixed a transient A→B session-replacement display gap; a regression test checks the transition. No signed-in Supabase/browser test was run. On 2026-10-20 the linked project's notification objects and migration-ledger version were verified; the dry-run showed four other migrations pending. The general migration list could not connect without the database password. Fresh local results and gaps are in `evidence/security-test-results.md`.

Status meanings: **Verified** = source mitigation plus relevant automated coverage and recorded pass evidence; **Partially mitigated** = meaningful controls but documented residual; **Unverified** = source/test or hosted behavior has not been established; **Not implemented** = no control found.

## STRIDE coverage and priority

| STRIDE threat | Asset and likely impact | Main controls and evidence | Priority / remaining limit |
|---|---|---|---|
| **Spoofing** | A stolen or forged identity could expose or change another user's documents. | Edge Functions verify tokens with Auth `getUser()`; actor identity is token-derived. Tests cover missing/forged tokens and body-supplied identity. | **High.** Stolen valid sessions remain usable until revoked/expired; real Auth/browser session tests were not run. |
| **Tampering** | Unauthorized file, metadata, role, or grant changes could alter document access or content. | Owner/editor authorization, service-role-only writes, RLS, server-validated uploads, immutable audit events. DB/API suites contain denial and upload tests. | **High.** Backend tests were not executable here; a privileged database/service-role compromise is outside app-level protection. |
| **Repudiation** | A user may deny an operation if actor/outcome evidence is missing or can be rewritten. | `app.write_audit` records the verified actor, action/outcome and request ID; admin queries resolve document names and user labels. Preview/download success is recorded after the object is fetched, integrity-checked and access is rechecked. Append-only triggers and the hash chain protect ordinary writes. | **Medium.** Some malformed requests fail before audit; a database owner can rewrite and recompute the entire chain. A server-prepared response does not prove a browser saved or displayed all bytes. |
| **Information disclosure** | IDOR, search, history, or recipient lookup could reveal files or metadata. | Per-request access checks, RLS, uniform inaccessible responses, owner-only grant details, no client Storage access. Tests cover guessed IDs, search leakage and document metadata. | **High.** Backend/live Storage checks were not run. Recipient suggestions intentionally reveal matching account emails to signed-in users. |
| **Denial of service** | Oversized uploads, repeated requests, or blocked audit locks can reduce availability. | Upload/body limits, supported format allowlist, throttling, recipient query limit, audit lock timeout. Tests cover size validation and throttling. | **Medium.** No global/IP limiter or workload queue; successful requests and platform quotas remain resource risks. |
| **Elevation of privilege** | A viewer may attempt to self-promote, create grants, or call admin/service operations. | Trusted role comes from `profiles.role`; guarded profile columns; owner-only share controls; service RPC privileges restricted. RLS/API tests cover role spoofing and unauthorized sharing. | **High.** First-admin bootstrap and privileged operator credentials need operational protection; backend suites were not run here. |

|---|---|---|---|---|
| **IDOR / cross-user access:** guess a UUID or change `document_id` to read, edit, or download another user's document. | All document decisions use `app.access_level` and `app.authorize_or_deny`; Edge Functions supply actor from Auth `getUser()`, not request body. | **Broken function-level authorization:** call an Edge Function or `svc_*` RPC directly, bypassing hidden buttons. | Every configured Edge Function has `verify_jwt=true`; wrapper calls Auth `getUser()`. | **Direct Storage API access:** call Storage API with anon/authenticated credentials or add an overly broad permissive policy. | `documents` bucket is private, 10 MiB, PDF/PNG/JPEG. Only Edge Functions use service credentials after authorization/audit; no signed URLs. `supabase/migrations/20261018000600_storage_bucket.sql`, `core.ts`. | `rls.test.ts` tests client denial and restrictive policy against a simulated permissive policy. | Real Supabase Storage API behavior was not covered by the SQL shim tests and must be integration-tested. | Unverified (live API); source/SQL-shim mitigation present |
| **Revocation / stale links:** recipient retains access after owner revokes or reuses a signed link. | No signed URLs; each preview/download is authorized against current DB state. Writes lock and re-check access. Revoke is committed before subsequent calls are evaluated. | `audit.test.ts` explicitly documents in-flight timing; `svc.test.ts` and `security.test.ts` test next-request denial. | Request authorized before revoke commits may finish. Bytes already downloaded/previewed, printed, captured, or copied cannot be recalled. | Partially mitigated |
| **Audit modification or forgery:** alter events, actor, outcome, sequence, or fabricate success. | `app.write_audit` is the only application insert path; role grants deny direct writes. Triggers assign sequence/hash, reject update/delete/truncate, and chain the head. Details reject sensitive key names and >4 KiB. Admin-only queries resolve event labels from database rows. Preview/download success is written after byte retrieval, integrity check and current-access recheck; the client cannot forge activity. See migrations 0300, 0500 and 20261020000300. | `supabase/tests/db/audit.test.ts` covers chain integrity; `svc.test.ts` covers delayed success and rechecked access; API tests cover successful/denied share, preview, download and revocation plus integrity failures; `frontend/src/tests/auditFormat.test.ts` ensures older records are not described as delivered. | DB owner/superuser can disable triggers, rewrite all rows and recompute the chain. Browser receipt/display is not observable by the server. Tests need a working disposable PostgreSQL/PostgREST harness; none ran in this environment. | Partially mitigated |
| **Malicious uploads / path traversal:** upload disguised executable/polyglot, spoof MIME/extension, oversized body, or choose an object path. | Handler caps body while reading; validator inspects PDF/PNG/JPEG signatures and terminators, checks extension and declared MIME, sanitizes filename. Server creates storage keys; SQL checks owner/document/key format. Hash and size rechecked before bytes are returned. | `security.test.ts` upload validation and hostile filename cases; `svc.test.ts` storage-key convention cases. | No antivirus, content disarm/sanitization, or robust polyglot detection. Viewer/browser parsers still process received bytes. | Partially mitigated |
| **Search metadata leakage / account enumeration:** search private titles, wildcard all rows, or enumerate users for sharing. | `search_documents` is invoker/RLS-respecting with explicit access filter and escaped LIKE wildcards. Recipient suggestions match display names/email usernames after 3 characters, exclude the caller, cap results at 20, and are audited/rate-limited. | `rls.test.ts` search leak/wildcard/visibility; DB/API recipient suggestion cases; frontend picker tests. | Signed-in searchers can discover emails matching names or email usernames; limits reduce bulk enumeration but cannot eliminate account discovery. Global publication intentionally exposes published metadata to signed-in users. Backend tests still need execution. | Partially mitigated; recipient discovery is an intentional sharing trade-off |
| **Session/token theft, XSS and account switching:** steal browser token, inject markup/script, or leave the prior user's view visible after account replacement. | Supabase JS persists sessions in browser storage; functions validate access token with Auth `getUser()`. React renders user strings as text. On user-ID change, `AuthContext` clears the old profile and gates protected routes until the new profile loads. Vercel headers and inline preview use CSP/`nosniff` controls. | `authGuard.test.tsx`, `authContext.test.tsx` direct session-replacement regression, `permissions.test.tsx`, and `apiClient.test.ts`. | The regression is frontend-mocked; real multi-tab Auth behavior is untested. XSS/browser extension/device compromise can access the current session; CSP has `style-src 'unsafe-inline'`; no MFA enforcement specified. | Partially mitigated |
| **CSRF / CORS:** trick browser into issuing state-changing cookie request or invoke API cross-origin. | API uses bearer Authorization header rather than ambient auth cookies; explicit CORS headers. Updated handler allows HTTP localhost/loopback ports dynamically for development and exact entries from `ALLOWED_ORIGINS` for other origins. `supabase/config.toml` requires gateway JWT; wrapper also verifies user. | `security.test.ts` checks denied evil origin and allowed localhost/preflight. | CORS is not an authorization control; non-local production origins must be correctly configured. Dynamic localhost rule is intentionally development-only and trusts loopback origins. | Partially mitigated; deployment config required |
| **Rate limiting / DoS:** flood lookups, invalid IDs, large uploads or audit writes. | Audit-derived throttle at 30 denied attempts/min, one marker/min; recipient lookup separately capped; body and file byte limits; 5 s DB lock timeout; gateway verifies JWT before functions. | `svc.test.ts` throttle and audit marker; `security.test.ts` upload size and validation; `audit.test.ts` concurrency. | No global/IP-based limiter or queue; successful reads/uploads can still consume resources; platform quotas are relied upon. | Partially mitigated |
| **Concurrency / grant-revoke races:** concurrent edits, permission changes, replacement or deletion leave stale access/duplicate grants. | Document row locking plus access re-check for writes; unique active grant constraint; transactional SQL service functions. Reads/downloads use current state at decision time. | `audit.test.ts` concurrent grants, grant/revoke, in-flight behavior and lock recheck; `svc.test.ts` grant history and revoke. | Already-authorized in-flight data operation may complete; globally serialized audit-chain writes limit throughput. | Partially mitigated |
| **Audit write failure:** deliver bytes or commit operation if the audit insert fails. | SQL service function performs authorized operation and audit in same transaction; exception aborts transaction. Edge Function fetches object bytes only after authorization/audit RPC succeeds. Storage/integrity errors return no bytes; cleanup is best effort. | `security.test.ts` fail-closed download case; `svc.test.ts` audit/error behavior. | Availability is sacrificed during audit DB/lock failures by design. Some best-effort error-event logging can fail without changing the original denial/error. | Verified* (fail-closed path) |
| **Notification spoofing / cross-user metadata disclosure:** forge a notice, read another user's notice, or treat a notice as document authorization. | `20261020000500_user_notifications.sql` creates notices only from trusted grant, global-share and successful edit/replacement audit triggers. RLS binds reads to `auth.uid()`; client writes are revoked; the read-state RPC updates only the caller's rows. Notice clicks use normal document routes and current authorization. Frontend tests cover unread state and new-event toasts; `supabase/tests/db/notifications.test.ts` defines privacy and write-denial cases. | `frontend/src/tests/notificationCenter.test.tsx`; remote policy/privilege metadata was checked, but DB regression bodies and signed-in browser delivery were not tested. | Stored notices include a title/actor snapshot and may remain visible to a former recipient after access revocation; they contain no document body or Storage key and do not restore access. Live authenticated Realtime and polling delivery remain unverified. | Partially mitigated |
| **Secret exposure:** leak service-role key through frontend, Git, logs, or audit details. | Service key is used by Deno Edge Functions and the trusted provisioning script; frontend uses only anon/publishable values. `.gitignore` excludes `.env`, keys and certificates. Audit detail constraints block common secret/content keys. | `rls.test.ts` and `svc.test.ts` contain relevant cases; this backend suite was not rerun in this session. | Manual operational hygiene remains necessary. The demo script can print its generated password once; never share output. Git history exists, but historical prompt summaries are not proof that no secret was ever present in earlier revisions. | Partially mitigated |
| **Privileged administrator/database compromise:** admin reads others' documents or DB owner rewrites policies/audit. | Admin can query audit and change limited user roles, but RLS/access model gives no document access by admin role. Service-role secrets restricted to functions. | `rls.test.ts` and `security.test.ts` explicitly test admin has no document access; audit tests cover ordinary-role tamper restrictions. | Supabase project owner, DB owner/superuser, compromised service-role key can bypass these boundaries; compromise is out of scope for app-layer controls. | Partially mitigated / privileged compromise accepted |
| **Previously downloaded copies and deletion:** revoke/delete but recipient retains local copy or provider backup. | New requests are denied after revoke/delete; delete soft-tombstones, revokes grants and attempts removal of all version objects, reporting `purge:'incomplete'` if removal fails. No signed links/cache. | `security.test.ts` verifies next access denial and harness object deletion; `svc.test.ts` checks deleted access. | Local copies, screenshots, exports, and provider backups cannot be recalled/are not managed. ## Pre-deployment evidence update — 2026-10-21

The current-source review checked the frontend access surfaces, Edge identity and file handlers, RLS/service-function boundaries, and the existing negative-test definitions. The build, frontend type-check, Deno type-check, and dependency audits passed. The first frontend suite run had one timeout; a full rerun passed (9 files, 30 passed, 1 todo). All DB/API cases skipped after setup failed to connect to local PostgreSQL. The browser check used dummy Supabase settings and was unauthenticated. These results do not verify hosted Auth, RLS, Storage object denial, revocation, or audit behavior.

Frontend text that implied app-provided AES-256 encryption or that every request is audited was corrected. Static Vercel configuration review also found that the PDF preview's `blob:` iframe was excluded by CSP; `frame-src 'self' blob:` is configured, but response headers and PDF rendering on Vercel remain untested. Since preview bytes are embedded through a Blob URL, the Edge response's CSP is not proof of the displayed document's isolation; browser-specific PDF preview/XSS behavior also remains untested. Encryption-at-rest configuration is provider-managed and was not verified here; client-side encryption is not implemented. Recipient-search account discovery remains the documented low-severity privacy trade-off. No database, hosted configuration, or deployment was changed.
