# TrustVault threat model

**Review basis:** source migrations, Edge Functions, frontend, and test definitions were inspected on 2026-10-19. “Verified” below means an automated test exists and the project history reports the baseline suites passing; it does not mean that the latest migrations or production Supabase service were independently tested in this review. Current CLI evidence at review time: migrations 0100–0800 recorded on the linked project; migration 0900 pending; nine functions active. Real hosted Auth/Storage behavior is not established by the local harness.

Status meanings: **Verified** = source mitigation plus relevant automated coverage and recorded pass evidence; **Partially mitigated** = meaningful controls but documented residual; **Unverified** = source/test or hosted behavior has not been established; **Not implemented** = no control found.

| Threat and attack scenario / impact | Actual mitigation and source | Automated test evidence | Residual risk | Status |
|---|---|---|---|---|
| **IDOR / cross-user access:** guess a UUID or change `document_id` to read, edit, or download another user's document. | All document decisions use `app.access_level` and `app.authorize_or_deny`; Edge Functions supply actor from Auth `getUser()`, not request body. RLS uses caller-bound `app.my_access_level`. Missing and inaccessible detail/downloads return uniform 404. See `supabase/migrations/20261018000200_access_helpers.sql`, `20261018000400_rls_and_privileges.sql`, `20261018000500_service_functions.sql`, `supabase/functions/_shared/core.ts`, `handlers.ts`. | `supabase/tests/db/rls.test.ts` cross-user/guessed-ID cases; `svc.test.ts` authorization; `supabase/tests/api/security.test.ts` cross-user/no-metadata cases. | Timing differences and authorized request already in flight can reveal limited signals. | Verified* |
| **Broken function-level authorization:** call an Edge Function or `svc_*` RPC directly, bypassing hidden buttons. | Every configured Edge Function has `verify_jwt=true`; wrapper calls Auth `getUser()`. Database operations authorize actor/access explicitly. Migration 0500 revokes client EXECUTE on `svc_*`, grants `service_role`; RLS has no client write policies for documents, permissions, versions, audit rows. | `rls.test.ts` function-exposure and direct-write tests; API auth and forbidden-operation cases in `security.test.ts`. | Hosted settings/function versions can drift from source; verify deployment separately. | Verified* |
| **Privilege escalation:** forge JWT/user metadata, promote self, alter another role, or make a new admin. | Role is read from `profiles.role`; signup metadata does not set it. Column grants/guard trigger protect profile fields. `svc_admin_set_role` only lets an admin change another non-admin between `owner`/`viewer`; no app endpoint creates/promotes admins. | `rls.test.ts` privilege-escalation and forged-claims cases; `svc.test.ts` admin rules; `security.test.ts` admin route tests. | Supabase project owner/service-role/database operator can change roles; initial admin bootstrap is an out-of-band privileged operation and must be controlled/logged operationally. | Verified* |
| **Direct Storage API access:** call Storage API with anon/authenticated credentials or add an overly broad permissive policy. | `documents` bucket is private, 10 MiB, PDF/PNG/JPEG. Restrictive RLS policy denies `anon` and `authenticated` for this bucket. Only Edge Functions use service credentials after authorization/audit; no signed URLs. `supabase/migrations/20261018000600_storage_bucket.sql`, `core.ts`. | `rls.test.ts` tests client denial and restrictive policy against a simulated permissive policy. | Real Supabase Storage API behavior was not covered by the SQL shim tests and must be integration-tested. | Unverified (live API); source/SQL-shim mitigation present |
| **Revocation / stale links:** recipient retains access after owner revokes or reuses a signed link. | No signed URLs; each preview/download is authorized against current DB state. Writes lock and re-check access. Revoke is committed before subsequent calls are evaluated. | `audit.test.ts` explicitly documents in-flight timing; `svc.test.ts` and `security.test.ts` test next-request denial. | Request authorized before revoke commits may finish. Bytes already downloaded/previewed, printed, captured, or copied cannot be recalled. | Partially mitigated |
| **Audit modification or forgery:** alter events, actor, outcome, sequence, or fabricate success. | `app.write_audit` is the only application insert path; role grants deny direct writes. Triggers assign sequence/hash, reject update/delete/truncate, and chain the head. Details reject sensitive key names and >4 KiB. Verification is admin-only and itself audited. See migration 0300 and 0500. | `supabase/tests/db/audit.test.ts` tests chain, append-only, edited/deleted rows, actor/outcome tampering, concurrency, and explicitly tests the known full-rewrite weakness; API tests cover audit authorization/fail-closed. | DB owner/superuser can disable triggers, rewrite all rows and recompute the chain. Copy chain head to independent storage. Audit writes serialize globally, with 5 s lock timeout. | Partially mitigated |
| **Malicious uploads / path traversal:** upload disguised executable/polyglot, spoof MIME/extension, oversized body, or choose an object path. | Handler caps body while reading; validator inspects PDF/PNG/JPEG signatures and terminators, checks extension and declared MIME, sanitizes filename. Server creates storage keys; SQL checks owner/document/key format. Hash and size rechecked before bytes are returned. | `security.test.ts` upload validation and hostile filename cases; `svc.test.ts` storage-key convention cases. | No antivirus, content disarm/sanitization, or robust polyglot detection. Viewer/browser parsers still process received bytes. | Partially mitigated |
| **Search metadata leakage / account enumeration:** search private titles, wildcard all rows, or enumerate users for sharing. | `search_documents` is invoker/RLS-respecting with explicit access filter and escaped LIKE wildcards. Recipient search requires ≥3 characters, max 20, audited, with 30 searches/minute/account. Owner grant resolves exact email and records denial; this can confirm registration. | `rls.test.ts` search leak/wildcard/visibility; `security.test.ts` recipient search and HTTP access. | Authenticated users can search matching registered names/emails; grant attempts may reveal an exact email exists. Global publication intentionally exposes published metadata to signed-in users. | Partially mitigated; residual accepted for sharing |
| **Session/token theft, XSS:** steal browser token or inject markup/script into names/filenames. | Supabase JS persists sessions in browser storage; functions validate access token with Auth `getUser()`. React renders user strings as text. Vercel config defines CSP, `nosniff`, `no-referrer`; inline previews use sandbox/CSP. | `authGuard.test.tsx`, `permissions.test.tsx` text-only rendering, `apiClient.test.ts` auth/header handling. | XSS/browser extension/device compromise can access current session; CSP has `style-src 'unsafe-inline'`; no MFA enforcement specified. | Partially mitigated |
| **CSRF / CORS:** trick browser into issuing state-changing cookie request or invoke API cross-origin. | API uses bearer Authorization header rather than ambient auth cookies; explicit CORS headers. Updated handler allows HTTP localhost/loopback ports dynamically for development and exact entries from `ALLOWED_ORIGINS` for other origins. `supabase/config.toml` requires gateway JWT; wrapper also verifies user. | `security.test.ts` checks denied evil origin and allowed localhost/preflight. | CORS is not an authorization control; non-local production origins must be correctly configured. Dynamic localhost rule is intentionally development-only and trusts loopback origins. | Partially mitigated; deployment config required |
| **Rate limiting / DoS:** flood lookups, invalid IDs, large uploads or audit writes. | Audit-derived throttle at 30 denied attempts/min, one marker/min; recipient lookup separately capped; body and file byte limits; 5 s DB lock timeout; gateway verifies JWT before functions. | `svc.test.ts` throttle and audit marker; `security.test.ts` upload size and validation; `audit.test.ts` concurrency. | No global/IP-based limiter or queue; successful reads/uploads can still consume resources; platform quotas are relied upon. | Partially mitigated |
| **Concurrency / grant-revoke races:** concurrent edits, permission changes, replacement or deletion leave stale access/duplicate grants. | Document row locking plus access re-check for writes; unique active grant constraint; transactional SQL service functions. Reads/downloads use current state at decision time. | `audit.test.ts` concurrent grants, grant/revoke, in-flight behavior and lock recheck; `svc.test.ts` grant history and revoke. | Already-authorized in-flight data operation may complete; globally serialized audit-chain writes limit throughput. | Partially mitigated |
| **Audit write failure:** deliver bytes or commit operation if the audit insert fails. | SQL service function performs authorized operation and audit in same transaction; exception aborts transaction. Edge Function fetches object bytes only after authorization/audit RPC succeeds. Storage/integrity errors return no bytes; cleanup is best effort. | `security.test.ts` fail-closed download case; `svc.test.ts` audit/error behavior. | Availability is sacrificed during audit DB/lock failures by design. Some best-effort error-event logging can fail without changing the original denial/error. | Verified* (fail-closed path) |
| **Secret exposure:** leak service-role key through frontend, Git, logs, or audit details. | Service key read only by Deno Edge Functions; frontend uses anon/publishable key. `.gitignore` excludes `.env`, keys and certificates. Audit detail constraint blocks common secret/content keys. | `rls.test.ts` confirms service-role cannot directly insert audit rows; `svc.test.ts` checks audit details. | Manual operational hygiene remains necessary. `scripts/provision-demo.mjs` uses service key from process environment and prints the demo password once; never share output. Workspace has no Git history. | Partially mitigated |
| **Privileged administrator/database compromise:** admin reads others' documents or DB owner rewrites policies/audit. | Admin can query audit and change limited user roles, but RLS/access model gives no document access by admin role. Service-role secrets restricted to functions. | `rls.test.ts` and `security.test.ts` explicitly test admin has no document access; audit tests cover ordinary-role tamper restrictions. | Supabase project owner, DB owner/superuser, compromised service-role key can bypass these boundaries; compromise is out of scope for app-layer controls. | Partially mitigated / privileged compromise accepted |
| **Previously downloaded copies and deletion:** revoke/delete but recipient retains local copy or provider backup. | New requests are denied after revoke/delete; delete soft-tombstones, revokes grants and attempts removal of all version objects, reporting `purge:'incomplete'` if removal fails. No signed links/cache. | `security.test.ts` verifies next access denial and harness object deletion; `svc.test.ts` checks deleted access. | Local copies, screenshots, exports, and provider backups cannot be recalled/are not managed. Failed Storage purge can leave inaccessible orphan objects. | Partially mitigated |

\* “Verified” refers to source plus test coverage and recorded historical baseline results in `docs/testing.md`; it is not a fresh run of the full backend suite or proof of live Storage behavior. Current hosted migration state and test evidence are recorded in `docs/PROJECT_STATUS.md`.
